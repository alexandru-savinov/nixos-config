- [x] Write `index/bin/transcript-archive`: scan closed sessions (mtime > 48h) under `projects/`, dedupe by looking up `sha256_plain` IN the canonical manifest (not by object-name existence), age-encrypt each new/changed source to an OPAQUE object named after its CIPHERTEXT hash — `soul-archive/YYYY/MM/<first-16-hex-of-sha256_cipher>.jsonl.age` — under the published dir, append manifest row `{ts,key,relpath,session,sha256_plain,sha256_cipher,bytes_plain,bytes_cipher,src_mtime}` (`relpath` = source path relative to `projects/`), atomic tmp+rename per object, manifest row written only AFTER its object lands. Cipher-hash naming (codex P2 on #576): a plaintext-hash name would let anyone holding a candidate transcript CONFIRM its presence and correlate equal plaintexts with no key at all; the cipher hash reveals nothing (age is non-deterministic) and doubles as a keyless name↔bytes integrity check. Content naming is also the collision/versioning fix (revmux-574 MAJOR): same-basename sources (68 `journal.jsonl` under `subagents/workflows/wf_*/`) get distinct objects, and a revived session becomes a NEW object beside the old one — nothing is ever overwritten

Snapshot refresh is NOT tied to "something changed" (codex P2 on #576): every run compares `sha256(MANIFEST.jsonl)` against the source hash recorded in `last-snapshot.json` and rewrites the snapshot on mismatch — this self-heals a crash between the canonical append and the snapshot rewrite, which would otherwise publish an object forever missing its identifying row

## Constraints
- NEVER delete, move, or rewrite source transcripts. Read-only on `projects/`.
- No new keys, no secrets in any output or chat: only PUBLIC age recipients in nix.
- The published dir carries ONLY ciphertext with opaque content-hash names. Plaintext `MANIFEST.jsonl`, `last-run.json`, and `INDEX.md` stay on choir outside the published dir — rpi5's pull (`remoteDir = "/"`) takes everything published, so any plaintext there (project names, session ids, sizes, timeline) breaks the zero-knowledge invariant.
- No third-party leg in v1; both endpoints are our hosts. Transport is the EXISTING mirror pull path: rpi5 → SSH to choir's PUBLIC IP (`soul-mirror-pull.nix` `remoteHost`, deliberately NOT a tailnet name — Tailscale SSH on choir authenticates by tailnet identity, skips `authorized_keys`, and would bypass the `rrsync -ro` forced command). The security boundary is age encryption at rest + key-bound forced command in transit, NOT the tailnet. Do not "fix" this by switching to a tailnet name — that weakens it (resolves the P1 on #574).
- Do not touch rpi5's pull mechanics in v1 (repairing the pull key, if the human's probe shows the vault empty, is a SEPARATE his-hand task already documented in the mirror module).
- Never push main; worktree + PR; merge is the human's word. Follow `nix fmt` before committing nix files.
- Archive placement must keep rrsync confinement intact — no endpoint widening beyond the published directory.
